CLEI `BVL3BCJFAA`. GPON vendor ID `CXNK` (Calix). The SFP EEPROM (`ethtool -m`)
reports vendor name `CALIX` and PN `GPON-LT004-0001`. The board is a T&W design,
identical to the [Zyxel PMG3000-D20B](/ont-zyxel-pmg3000-d20b); the exact T&W
model number is unconfirmed. The 100-05609 is the SFP ONT that ships inside the
Calix GigaSpire u6x (GS4227). Its XGS-PON sibling, the 100-05610, uses the newer
MaxLinear PRX300 SoC.

The Falcon's MT (Multi-Threading) ASE provides two virtual processing elements
on one core. VPE0 runs Linux; VPE1 runs the GPON real-time firmware (burst-mode
TDMA timing, PLOAM, DBA responses) on a dedicated hardware thread that Linux
cannot preempt.

# Optical Specifications

Class B+ GPON optics, 2.5G downstream / 1.2G upstream (G.984.2).

| Parameter        | Value          |
| ---------------- | -------------- |
| Connector        | SC/APC         |
| Tx wavelength    | 1310 nm        |
| Min Tx power     | +0.5 dBm       |
| Max Tx power     | +5 dBm         |
| Rx sensitivity   | −27 dBm        |
| Rx overload      | −8 dBm         |
| Power budget     | 28 dB          |
| Operating temp   | 0–85 °C        |
| Reach            | 20 km          |

::: info Note
The I2C EEPROM (A2h) TX-power alarm thresholds are burned from a **Class B**
template, not Class B+: TX high and low both sit at ±3.01 dBm, with no headroom
band. On a part rated to +5 dBm, the +3.01 dBm high alarm can trip during normal
B+ operation; the −3.01 dBm low alarm will not fire until 3.5 dB below the B+
floor. Read with `ethtool -m` from the host.
:::

# Architecture

The SFP is a full GPON ONT. It presents a single host-side SerDes link
(SGMII/2500BASE-X) to the carrier board and terminates GPON and OMCI internally.
Behind a GigaSpire u6x it runs in `work_mode=2`: it TFTP-boots a RAM image from
the host (169.254.1.2) on every power cycle and runs entirely from RAM. The
flash slots hold fallback firmware for `work_mode=1` (standalone) operation.

```
u6x host (169.254.1.2) ── VLAN 4094 mgmt plane ── Calix SFP (169.254.1.1) ── GPON OLT
```

Subscriber traffic flows through the Falcon hardware switch fabric
(OMCI-programmed GEM-to-VLAN forwarding), not through the Linux `host`
interface. Linux interface counters show management traffic only; use the `onu`
hardware counters for data-plane statistics (see
[`onu` CLI](#onu-cli)).

# Serial

The board has a Lantiq TTL UART console (`ttyLTQ0`, 3.3V, 115200 8-N-1), broken
out to pads on the PCB. It is the ground-truth console for boot and for the
DSMP/dcli event bus to the host RG.

The 100-05609 is the same T&W board design as the
[Zyxel PMG3000-D20B](/ont-zyxel-pmg3000-d20b), on the same Lantiq FALC ON SoC.
The UART pad order matches, confirmed working; that page has a labelled
[pinout photo](/ont-zyxel-pmg3000-d20b#serial).

# Root procedure

Dropbear (SSH) listens on port `30007` on the host-side management plane. From
the carrier board (which holds `169.254.1.2` on VLAN 4094):

```sh
ssh -o StrictHostKeyChecking=no -p 30007 support@169.254.1.1
# password: support
```

The same EXOS IPv6 firewall bypass applies as on the
[GP1100G](/ont-calix-gp1100g#root-procedure): the OLT-pushed firewall carries
only IPv4 rules for port 30007, and `ip6tables` is never loaded, so IPv6
link-local SSH reaches a root shell with the hardcoded `support` / `support`
credentials.

::: info Note
Shell access persists only while the SFP stays powered in a host cage. The
host-side interface binds `169.254.1.1` only after a DSMP handshake from the RG
peer; a bare SFP in a generic cage needs that handshake (and an RX_LOS / GPIO
override) before the link comes up.
:::

# GPON ONU status

## Identity

The GPON identity lives in the `nvram` partition (`mtd8`), CRC-protected like
the GP1100G. Fields are read and set with the Calix `flash` helper
(`/etc/scripts/flash get|set <KEY>`). Relevant keys:

| Key                | Meaning                          |
| ------------------ | -------------------------------- |
| `PON_VENDOR_ID`    | GPON vendor ID (`CXNK` for Calix) |
| `GPON_SN`          | FSAN serial number               |
| `GPON_PLOAM_PASSWD`| PLOAM password                   |
| `ELAN_MAC_ADDR`    | base MAC                         |
| `GPON_ONU_MODEL`   | model string (`100-05609`)        |
| `HW_SERIAL_NO`     | manufacturing serial             |
| `OMCI_OLT_MODE`    | OLT compatibility mode           |

As on the GP1100G, a matching FSAN serial number is the link key on the Calix E7
plant tested, where the operator provisions each ONT by hand in Calix SMx. A
matching serial reaches `O5` without a PLOAM password or Registration ID. This is
plant-dependent: see
[OLT authentication](/ont-calix-gp1100g#olt-authentication) for plants that use
a PLOAM password or RONTA Registration ID.

## `onu` CLI

The MaxLinear/Lantiq diagnostic CLI is `/opt/lantiq/bin/onu`. It reads
hardware-level GPON, GTC, GEM, and host-port counters that the Linux stack does
not expose. Common read commands:

| Command        | Purpose                                        |
| -------------- | ---------------------------------------------- |
| `onu gtcsg`    | GTC status (PLOAM state, ONU ID, ranging)      |
| `onu ploamsg`  | PLOAM FSM state                                |
| `onu lanpsg 0` | host-side port status (mode, speed, duplex)    |
| `onu lantcg 0` | host-side total counters (TX drops, FCS errors)|
| `onu gtctcg`   | GTC total counters (TC-layer errors)           |
| `onu gpebptcg` | GPE bridge-port total counters                 |

`lanpsg` speed field: `4` = 1000M, `5` = 2500M. The LAN and GPE counters are
unsigned 32-bit hardware registers that wrap silently at `0xFFFFFFFF`; reset
with `onu lancr 0` / `onu gpebpcr` before taking a delta.

::: warning Note
Several `gtctcg` fields are derived, not independent reads. `drop` is a four-term
driver sum (`gem_herr_2 + fcserr + ovrsize + reasserr`), `rx_gem_frames_dropped`
reads the same register as `hec_error_uncorr`, and `rx_gem_bytes_total` is always
0. Read raw `fcserr` / `reasserr` from `/proc/driver/onu/ictrlg` instead.
:::

# Known Bugs

- **IPv6 firewall bypass (root).** Same EXOS flaw as the GP1100G: `ip6tables`
  unloaded, dropbear on port 30007, hardcoded `support` / `support`.
- **Class B EEPROM thresholds on a B+ part.** TX-power alarm/warning thresholds
  are mis-templated (see [Optical Specifications](#optical-specifications)).
